# 机鉴 · IDC AI 故障调查台

一个本地私有化的 IDC 故障调查与现场协同产品骨架。机鉴本身仍可零第三方依赖运行，也可以连接 SigNoz Community 获取真实日志、指标和告警，并连接 HolmesGPT 执行带工具记录的只读 AI 调查。它将原始输入、外部查询、字段来源、可核对事实、知识卡、竞争假设和下一步检查整理成一条可审计调查链。

当前版本不会把关键词匹配冒充已经确认的 AI 根因，也不会把演示数据冒充真实设备数据。

## 立即启动

要求 Python 3.9 或更高版本。

```bash
cd /Users/a0000/.codex/.chatgpt-projects/g-p-6a89daf197708191b93f386ec2b56df1/idc-ai-ops
python3 run.py
```

然后打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。macOS 也可以双击 `start.command`。

事件默认保存在 `data/incidents.db`，关闭再启动不会丢失。

## 首版能力

- 通用监控告警接口：`POST /api/ingest/alert`
- 日志上传或粘贴：Linux、内核、磁盘、内存、网络和应用运行日志
- 现场异常上报：完整 SN、机架位、UID、重装发起和电源权限
- 规则优先、可选模型增强的故障分类与证据整理
- 同一事故的多条输入、多台设备关联
- 现场处置卡与操作安全门
- Linux、应用、网络与机房设施共 13 个页面回放场景
- 核心/普通/未确认三种机房等级，以及供电、漏水、核心网络、温度和烟雾三态 CC 判断
- CC 只在确定性规则或人工明确确认时显示一次电话提醒，不接管后续电话流程
- 36 组完整合成日志、259 个自动检查点，覆盖系统、应用、网络和设施故障
- 可见数据库：事件、原始输入、审计记录和机房档案可在页面查询
- 48 张版本化经验知识卡、4 组可编辑提示词，以及草稿/测试/两步上线/回滚
- 每次分析自动保存 8 步 RAG 链路，显示知识命中原因和模型是否真实执行
- 现场操作闭环：OMS 不可变快照、完整 SN 核对、操作许可、第二人复核、开始/成功或失败接单
- 本地、合作厂商私有化、经授权云模型三类适配入口；未连通时明确显示未连通
- 六类接入实验室：动环/DCIM、网络NMS、BMC/Redfish、Linux/应用、OMS/CMDB、现场反馈分别模拟连接、断开、延迟、降级、权限不足和无效返回
- 确定性跨平台归并：明确事故号，或准确设备身份＋已登记拓扑＋时间窗口＋兼容信号；只凭文本相似不会自动合并
- AI 主动只读调查：真实模型逐轮选择获准查询工具；测试模型桩明确标记为“非真实AI”；每轮依据、工具返回、证据和假设变化可审计
- 五种角色后端字段隔离；最高管理员可在填写原因并再次确认后查看原始记录，访问行为会进入审计
- SQLite 一致性在线备份、SHA-256 校验与恢复可读性检查
- 生产告警治理：来源健康、确定性设备身份、重复/恢复、维护静默、上游抑制、责任分派和人工纠正
- 六类公开测试数据目录：许可证可见、轻量样本本地缓存、导入哈希与报告；公开数据不冒充客户现场

## 页面怎么用

- **事件**：查看真实或模拟故障的证据、候选原因、反证、下一步和现场处置卡。
- **真实故障**：粘贴日志，或由现场填写实际观察；系统不会把输入内容假装成已确认根因。
- **模拟案例**：运行内置场景，熟悉产品流程；所有模拟内容都带明确标记。
- **数据来源**：查看日志、告警和外部调查工具是否真正连通。
- **告警治理**：查看信号怎样经过来源、身份、降噪、事故和责任五道闸门；测试重复、恢复、维护、上下游抑制和值班分派。
- **机房等级**：在暂未接入资产平台时，先标记核心/普通/未确认机房。
- **数据与 AI**（AI 管理员）：查看数据库、编辑经验知识与提示词、回放 RAG 链路、配置模型适配器、测试并上线版本。
- **现场操作**：导入 OMS 工单快照，核对完整 SN，分别确认操作许可和人工复核，最后提交成功或失败结果。
- **接入实验室**（AI 管理员/最高管理员）：切换六个平台状态、发送模拟平台信号、运行跨平台场景、查看归并依据、启动 AI 只读调查、查看拓扑并创建数据库备份。

### 告警治理最快使用路径

1. 左下角切换为“最高管理员”，打开“告警治理”。
2. 在“告警与降噪”发送默认网络告警；再次发送会增加出现次数，不会重复创建事故。
3. 把 JSON 的 `lifecycle_status` 改为 `recovered`，观察“恢复待验证”；监控恢复不会直接关闭事故。
4. 在“可信数据”模拟采集器断开或写入两个冲突的机架位，观察来源异常和身份阻断。
5. 在“值班与责任”登记夜班、分派事故并确认收到；系统记录责任链，但不代替人工授权。
6. 在“公开数据测试”查看许可证后导入允许的轻量样本。LogHub 仅用于研究测试；大体量或许可不清晰的数据不会打包进入产品。

左下角可以切换角色和当前账号。现场人员、机房组长、接口人、AI 管理员和最高管理员看到的事件字段不同；操作人与复核人必须使用不同账号。角色限制不仅是隐藏按钮，服务端接口也会拒绝越权请求。当前仍是本地演示身份头，生产环境必须替换为真实登录与组织权限。

### 接入实验室最快使用路径

1. 左下角切换为“最高管理员”，打开“接入实验室”。
2. 在“平台与信号”确认六个平台状态；可把任一平台切到断开、延迟或权限不足，观察真实失败分支。
3. 运行“网络模块/端口故障引发连锁异常”，在信号总线查看 NMS、BMC、Linux 和应用信号为何进入同一事故。
4. 打开“AI 调查轨迹”，先选“测试模型桩（非真实AI）”验证工具链；配置真实模型后再选“真实模型 Agent”。
5. 最高管理员可展开每轮结构化依据；如必须看原始模型交换或平台载荷，使用突破性访问并填写原因。
6. 在“拓扑与备份”查看身份映射来源，并创建一次经过一致性与恢复读取校验的数据库备份。

## 复合底座

- **SigNoz Community**：独立部署的日志、指标、告警和查询底座；机鉴不复制其界面和源码。
- **OpenTelemetry Collector**：在获准的 Linux 主机采集 journald 与主机指标并发送到 SigNoz。
- **HolmesGPT**：可选只读 AI 调查服务，返回回答和工具调用记录。
- **机鉴**：保留 IDC 特有的完整 SN/机架位、事件关联、现场安全门、OMS 操作闭环和经验资产。

连接说明见 [SigNoz 与 HolmesGPT 连接说明](docs/integrations/signoz-holmes-setup.md)，第三方边界见 [THIRD_PARTY.md](THIRD_PARTY.md)。当前开发电脑没有 Docker，因此仓库不会把“已经写好连接器”冒充为“SigNoz 和 HolmesGPT 已经运行并采到真实客户数据”。

## 数据是怎么进入系统的

当前支持三种直接入口，以及两种可选的自动调查来源：

1. 用户在浏览器粘贴或上传日志；
2. 现场人员填写观察结果；
3. 外部监控平台主动调用通用 Webhook。
4. 配置后由机鉴按设备身份和事故时间窗查询 SigNoz。
5. 配置后由 HolmesGPT 调用获准的只读工具补充调查。

部署模板分别位于 `deploy/otel/linux-agent.yaml`（Linux journald 与主机指标）和 `deploy/otel/network-syslog.yaml`（受控网络中的交换机 syslog）。模板不会自动运行，也不会绕过客户授权。

内置案例由程序生成模拟输入，页面会始终显示“模拟数据”。机鉴不会自动登录 Linux、扫描未知目录或越权查询 BMC、OMS 和交换机；“数据来源”页面会如实显示哪些来源可用、未配置、失败或仍需客户接口。

## 一条结论怎样形成

```text
保存原始输入与来源
  → 记录 SN/机架位等字段是谁提供的
  → 从原文提取设备、端口、错误码和指标等事实
  → 记录命中的规则及其能力边界
  → 用事实检索结构化知识卡
  → 形成多个竞争假设、反证条件和缺失证据
  → 说明事件为什么合并或为什么不合并
  → 选择风险最低、信息增益较高的下一项检查
  → 以“已确认/较大可能/调查候选/证据不足”展示结论
```

完整 SN、机架位、UID 和操作许可默认视为外部报告值，不视为 AI 推断或系统已经核验。没有物理槽位映射时，系统不会猜测具体盘位或 DIMM 位置。

## 诊断知识库

`knowledge/diagnostic_cards.json` 内置 48 张带来源和版本的知识卡，覆盖存储、内存/CPU、网络、动环、Linux 系统和应用六个领域。每张卡包含：

- 可观察症状和支持信号；
- 竞争原因和会削弱判断的情况；
- 缺失上下文、下一步检查和分支条件；
- 停止条件和禁止推断；
- 官方规范或项目文档来源。

本轮使用确定性标签检索，不依赖向量数据库。知识覆盖不足时返回“知识覆盖不足”，不让模型用常识补造答案。

## 通用告警示例

```bash
curl -X POST http://127.0.0.1:8765/api/ingest/alert \
  -H 'Content-Type: application/json' \
  -d '{
    "site": "BJYZ",
    "severity": "critical",
    "sn": "SERVER-FULL-SN-001",
    "device_name": "bjyz-compute-001",
    "rack_position": "BJYZD2MC-A-01-01",
    "device_type": "server",
    "summary": "服务器网络链路中断",
    "message": "interface eth0 link down",
    "uid_status": "on",
    "power_permission": "forbidden"
  }'
```

多个告警属于同一事故时，监控侧可以提供相同的 `incident_key`，系统会将它们合并为一个多设备事件。没有明确共同标识时，不同完整 SN 默认不会被强制合并。

SigNoz/Alertmanager 风格告警可发送到 `POST /api/ingest/signoz-alert`。对已有事件调用 `POST /api/incidents/{事件ID}/investigate` 时，机鉴会执行一次受限的 SigNoz 查询和可选 HolmesGPT 调查，并把成功、失败或未配置状态都写入证据链。

## 可选 AI 增强

默认不把任何数据发送到外部模型。要使用客户内网或兼容 OpenAI Chat Completions 的模型接口，显式配置：

```bash
export IDCAI_ALLOW_EXTERNAL=1
export IDCAI_MODEL_URL='http://your-private-model/v1/chat/completions'
export IDCAI_MODEL='your-model-name'
export IDCAI_API_KEY='optional-key'
python3 run.py
```

调用模型前会对疑似密钥、令牌和邮箱脱敏；模型接收的是已提取事实、证据、召回知识卡和基线候选，不负责设备身份或操作许可。主动 Agent 只能调用登记过的只读查询工具，所有查询固定绑定已经形成的事故 ID，不能让模型临时猜 SN、机架位、端口或拓扑。模型输出必须引用已有证据，不能使用未经工具验证的 `confirmed`，不能建议危险操作；输出无效时会明确记录失败，不生成伪造结论。

“测试模型桩”只用于验证 Agent 协议、平台查询和轨迹回放，不证明大模型能力。提示词或知识草稿的自动测试也只做结构与流程检查；通过不等于内容事实正确，仍需人工核对来源、适用条件、禁用条件和现场风险。

提示词契约位于 `prompts/contracts.json`，分为事实解析、假设生成、下一步调查和角色化沟通四种职责。默认模型关闭时，页面明确显示“规则＋知识”，不会显示为 AI 已经完成调查。

## 安全边界

- 默认本机监听 `127.0.0.1`，不向公网暴露。
- 如需在受控内网监听其他地址，必须显式设置 `IDCAI_ALLOW_LAN=1`；跨域访问另需设置 `IDCAI_ALLOW_CORS=1`。
- 不读取代码仓库，不扫描未知目录。
- 不执行关机、重启、拔盘、改配置或任何基础设施写操作。
- AI 提供的是调查结论和建议，不是现场操作授权。
- 完整 SN、机架位、业务状态或操作许可不一致时，处置卡要求停止并联系接口人。
