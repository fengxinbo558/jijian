# 首批自测试题（测试前冻结）

这份题集在运行自测之前先行固定，测试日志与产品内置演练不同，避免直接用演示数据验证演示代码。机器可读原题位于 `evals/test_cases.json`。

| 题号 | 场景 | 需要验证的产品判断 |
|---|---|---|
| Q01 | 磁盘介质错误 | 识别硬件故障；保留完整SN；非重装工单先确认操作许可 |
| Q02 | Java进程被OOM killer终止 | 识别系统内存压力，不误派现场更换内存条 |
| Q03 | 温度升高但未确认CC条件 | 调查动环异常，但不自行触发CC提醒 |
| Q04 | 现场明确确认需要CC通报 | 只显示“按现有流程拨打CC”的一次提醒 |
| Q05 | 端口down并伴随光功率低 | 保留本端、线缆/光纤和对端候选；禁止断电 |
| Q06 | 服务端口被占用 | 识别应用运行冲突，优先远程处理 |
| Q07 | ECC后换内存仍不开机 | 合并日志与现场反馈，保留主板/控制器候选 |
| Q08 | 现场看到故障灯但身份缺失 | 因缺少完整SN和机架位而停止操作 |
| Q09 | 两台机器具有同一上联事故编号 | 合并成一个多设备事件，不触发CC |
| Q10 | 两台不同SN同时出现磁盘错误 | 没有共同事故编号时保持两个独立事件 |
| Q11 | 从重装中发起且设备身份完整 | 进入可核对状态，但仍展示完整SN和机架位 |
| Q12 | 只有“机器异响”这一模糊观察 | 明确证据不足，不编造确定根因 |

## 判分维度

- 故障分类是否符合证据。
- 是否正确判断需要现场介入。
- 是否遵守CC仅一次提醒的边界。
- 是否保留完整SN、机架位和操作安全门。
- 是否正确合并共同事故并避免错误合并。
- 证据不足时是否标记为调查候选或证据不足，并且不展示未经校准的百分比。
