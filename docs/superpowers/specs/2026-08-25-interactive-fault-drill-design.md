# 交互式故障演练台与故障影响路径设计

日期：2026-08-25

状态：待用户书面复核

适用产品：机鉴 · IDC AI 故障调查台

## 1. 背景

机鉴已经具有真实故障入口、模拟案例、六类平台接入实验室、确定性身份与拓扑关联、告警治理、RAG 链路、AI 只读调查、现场操作闭环和角色权限。但是当前模拟体验仍有三个问题：

1. “模块/端口/链路异常”等多个原因被放在一个大场景中，不够具体；
2. 跨平台信号几乎一次性注入，用户看不到系统怎样逐步获得证据、改变候选并转交责任人；
3. 现有拓扑只能说明资产关系，不能直观看出故障节点、影响链、当前调查位置和实际维修路径。

本设计新增一个仅管理角色可用的“故障演练台”。操作者选择或随机抽取一个具体故障后，模拟平台通过与未来真实平台相同的接口逐步发送信号。系统必须自己完成接收、身份核验、关联、降噪、调查、责任分派和恢复验证，不能由场景直接把答案传给分析程序。

## 2. 产品目标

### 2.1 目标

- 把抽象模拟案例改造成可以直接触发的具体故障库；
- 用真实接入边界驱动整条产品链，而不是在浏览器播放固定动画；
- 自动完成适合 AI 的信息收集、只读查询、证据整理、候选比较和沟通草稿；
- 在身份确认、操作许可、换件、断电、现场判断和最终关闭等责任点暂停等待人工；
- 用物理定位卡和本次故障影响路径展示位置、受影响范围、调查状态和恢复状态；
- 用动态处置路径展示“根据什么做了什么、结果怎样、下一步为何改变”；
- 支持定向演示和隐藏答案的盲测验收；
- 用可重复的成绩单比较规则基线、知识版本、提示词版本和真实模型版本。

### 2.2 非目标

- 不在首版模拟十万台服务器或完整数据中心数字孪生；
- 不模拟交换机转发芯片、路由协议和电力系统的全部底层行为；
- 不连接或操作未经授权的真实设备；
- 不把固定场景答案、测试模型桩或规则输出包装成真实 AI 定位；
- 不让模型猜测完整 SN、机架位、端口、上下联、业务归属或操作许可；
- 不用模拟通过率宣称十万台真实生产准确率；
- 不展示模型不可见的私有逐字思维，只展示显式任务说明、工具调用、证据、候选变化和规则拦截。

## 3. 已确认的产品决策

1. 采用“事件驱动演练引擎＋物理定位卡＋故障影响路径”，不采用固定动画、完整机房大图或完整数字孪生；
2. 采用混合式演练：自动运行到人工责任点后暂停，接收反馈再继续；
3. 同时提供定向演示和盲测验收；
4. 维修过程由检查结果驱动下一步，不强迫所有场景走到预设终点；
5. 提供自动播放、单步推进和跳到下一人工节点三种控制方式；
6. 首批建立网络、系统/Linux、服务器硬件/现场、动环、应用五类共 25 个具体故障；
7. 不要求用户手绘完整机房图；没有真实资产关系时使用明确标记的测试拓扑，后续由 CMDB、OMS 和 NMS 数据替换。

## 4. 总体架构

```text
故障库 / 随机盲测
       ↓
演练控制器 ─────────→ 隔离答案区
       ↓                 仅评分器可读
平台信号计划
       ↓
动环 / NMS / BMC / Linux / 应用 / OMS / 现场模拟器
       ↓
现有统一平台接入口
       ↓
原始快照与来源健康
       ↓
身份核验 → 拓扑关联 → 去重 / 维护静默 / 上游抑制
       ↓
事故、规则与知识基线、可选真实 AI 只读调查
       ↓
自动步骤 ──→ 人工责任点暂停 ──→ 现场或接口人反馈
       ↑                              ↓
       └──────── 新证据与新信号 ──────┘
       ↓
监控恢复 → 业务验证 → 人工确认结束
       ↓
结果与隔离答案对比、成绩单和可审计回放
```

系统新增五个边界清晰的组件：

1. **故障目录**：描述可触发故障，不执行分析；
2. **演练控制器**：管理运行、时钟、播放方式、暂停点和分支；
3. **模拟平台适配器**：按计划通过现有统一接口发送原始信号；
4. **物理定位与影响路径视图**：读取资产关系和调查状态，不参与根因判断；
5. **盲测评分器**：演练结束后读取隔离答案并与实际结果比较。

现有生产处理链保持唯一，不为演练另写一套“快速答案”逻辑。

## 5. 安全隔离与防止演练作弊

### 5.1 隐藏真相

每个场景包含 `hidden_truth`，至少记录真实故障类型、故障实体、故障部件、影响范围和可接受结论。该字段必须满足：

- 不进入平台事件；
- 不进入事故、RAG、提示词、知识检索或模型上下文；
- 不通过普通场景接口或角色化事件接口返回；
- 定向演示只在演练控制区向操作者显示题目名称，不把答案注入分析链；
- 盲测运行期间仅评分服务可读取；
- 演练完成或终止后才允许最高管理员揭示答案。

### 5.2 同一处理链

所有模拟信号必须调用现有平台事件接口或相同服务合同，接受与真实信号一致的：

- 结构校验；
- 来源状态校验；
- `source_system + source_event_id` 幂等去重；
- 原始载荷保存；
- 确定性设备身份；
- 拓扑和时间窗口关联；
- 告警降噪；
- 事故形成和调查；
- 角色投影与审计。

前端不能直接创建“已定位模块故障”的结果卡。

## 6. 演练模式与控制

### 6.1 定向演示

操作者明确选择具体故障。页面可显示演练题目和教学目标，但分析系统仍只接收逐步产生的信号。适合产品展示、培训和流程说明。

### 6.2 盲测验收

操作者只选择故障分类、难度或随机范围，服务端随机抽取具体场景。运行期间不返回故障名称、真实部件和预期路径。适合比较规则、知识、提示词和模型版本。

### 6.3 播放控制

- **自动播放**：按场景相对时间自动产生信号，遇到人工节点暂停；
- **单步推进**：每次推进一个平台信号、一次自动调查或一次状态变化；
- **跳到人工节点**：连续执行安全的自动步骤，在下一个人工责任点暂停；
- **暂停/继续**：暂停时不产生新信号，但允许查看已有证据；
- **终止演练**：保存终止原因和当时状态，不把它记为成功；
- **重新开始**：创建新的运行编号，不覆盖旧运行。

演练采用逻辑时钟。界面可以快速播放，但事件仍保留相对顺序和时间间隔，便于测试迟到、乱序和超时。

## 7. 动态维修与调查分支

场景不保存一条必须走完的固定维修路线，而保存“节点、可接受反馈、分支条件和结束条件”。例如端口抖动可能出现：

```text
端口抖动
  ├─ 查询配置异常 → 网络组修改或回滚 → 监控与业务验证
  └─ 配置正常
       ├─ 更换模块后恢复 → 模块故障 → 监控与业务验证
       └─ 更换模块后仍抖动
            ├─ 光功率异常 → 检查本端/对端/光纤
            │    ├─ 换线恢复 → 线路问题 → 监控与业务验证
            │    └─ 换线无效 → 对端或端口硬件继续调查
            └─ 光功率正常 → 端口硬件、对端或上层协议继续调查
```

每一个步骤必须包含：

- 步骤发起者：系统自动、AI、接口人或现场人员；
- 动作等级：只读查询、人工观察、人工授权或现场操作；
- 输入证据和候选；
- 可接受反馈及校验规则；
- 反馈产生的新证据；
- 下一分支和停止条件；
- 是否需要完整 SN、机架位、UID、操作许可或双岗复核；
- 失败、无效、无法执行和证据不足的去向。

如果中途恢复，流程立即进入恢复验证，不继续执行无意义步骤。所有可做检查完成仍不能确认时，合法结束为“证据不足/升级处理”，不能强行猜答案。

## 8. 首批故障目录

第一版建立 25 个具体故障：

### 8.1 网络

1. 光模块故障或性能退化；
2. 光纤衰耗、弯折或断纤；
3. 交换机端口硬件故障；
4. 端口配置、聚合或协议异常；
5. 交换机整机或上联故障。

### 8.2 系统 / Linux

1. OOM 导致进程被终止；
2. 磁盘 I/O 错误及文件系统只读；
3. systemd 服务重启循环；
4. Linux 网卡 carrier、bond 或驱动异常；
5. 内核软锁死、watchdog 或严重内核异常。

### 8.3 服务器硬件 / 现场

1. 硬盘 SMART 预测故障；
2. ECC 内存异常；
3. 电源模块故障；
4. 风扇故障；
5. 更换已报部件仍无法启动后的疑似主板故障。

### 8.4 动环

1. 核心机房单路掉电；
2. 双路掉电；
3. 制冷异常导致区域高温；
4. 漏水影响设备或核心网络；
5. 烟雾告警。

### 8.5 应用

1. 监听端口冲突；
2. 下游依赖连接超时或拒绝；
3. DNS 解析异常；
4. TLS 证书过期；
5. 数据库死锁。

现有合成日志和生产闭环场景可以作为原始材料，但每个新场景必须重新明确隐藏真相、初始症状、平台信号、拓扑、动态分支、人工责任点和恢复条件。

## 9. 场景与运行数据合同

### 9.1 场景定义

每个版本化场景至少包含：

- 场景 ID、版本、分类、难度、教学目标；
- 可见初始症状；
- 隔离隐藏真相；
- 测试拓扑引用；
- 平台连接初态；
- 相对时间信号计划；
- 自动调查检查点；
- 人工节点和动态分支；
- 支持证据、反证和不得推断内容；
- 责任组和转交流程；
- 监控恢复、业务恢复和人工结束条件；
- 可接受的替代结论；
- 评分规则。

### 9.2 演练运行

每次运行单独保存：

- 运行 ID、模式、状态、逻辑时钟和操作者；
- 场景版本；
- 知识、规则、提示词、模型和拓扑版本；
- 逐条平台信号和真实接口响应；
- 告警、事故、关联、抑制和身份冲突；
- AI 或基线每轮查询、证据和候选变化；
- 每次人工反馈、授权、操作、操作者和时间；
- 走过的分支、未执行分支及原因；
- 恢复与业务验证；
- 最终结果和评分。

历史运行只追加，不因场景或知识升级而重写。

## 10. 页面设计

“故障演练台”只对 AI 管理员和最高管理员显示，并由服务端拒绝其他角色的触发和答案访问。

### 10.1 故障库

- 五个分类页签；
- 搜索、难度、是否需要现场、责任组和风险筛选；
- 故障卡显示模拟目标、可能信号、责任组和是否需要现场；
- 盲测模式只允许选择范围，不展示被抽中的具体故障。

### 10.2 演练控制台

- 模式、播放方式、运行状态和逻辑时间；
- 当前步骤、已收到信号、当前调查动作；
- 暂停、继续、单步、跳到人工节点、终止和重开；
- 清楚显示“规则＋知识”“测试模型桩（非真实 AI）”或“真实模型”；
- 人工节点提供结构化选项和补充说明，未知结果允许填写但必须标记未结构化。

### 10.3 物理定位卡与故障影响路径

不绘制包含全部排、机柜和设备的完整机房大图。页面提供两张相互独立的轻量视图：

1. **物理定位卡**：只显示当前事故涉及的 `机房 → 排/区域 → 机柜 → 机架位 → 设备`，用于现场找设备；
2. **故障影响路径**：只显示本次事故有证据支持的相关节点和链路，用于解释故障传播与调查范围。

影响路径必须区分不同网络语义，不能把它们强行画成一条直线：

- 业务东西向示例：`服务器 → ToR/Leaf → Spine → Leaf → 服务器`；
- 业务南北向示例：`服务器 → ToR/Leaf → Spine → Border Leaf/DCI → 外部网络`；
- 带外管理示例：`运维管理端 → 管理汇聚 → iLO/BMC 管理交换机 → BMC`；
- 应用服务示例：只在资产或流量证据表明业务经过时显示 `ADC/负载均衡 → 应用服务`。

`ToR` 在很多架构中本身承担 Leaf 角色；如果真实环境中服务器接入交换机和 Leaf 是两层设备，必须由 CMDB/NMS 明确提供关系。`超核`、`普核`等现场称呼作为可配置显示别名保存，不自动映射为 Super Spine、Spine、Core 或 Border。ADC 是服务节点，不作为所有链路的必经层。

模块或线路故障时，影响路径优先收缩为：

```text
交换机端口 → 光模块 → 光纤/网线 → 对端端口 → 受影响服务器/业务
```

状态颜色：

- 红色：有直接故障证据；
- 橙色：受影响但尚未确认根因；
- 蓝色：正在调查；
- 绿色：已经验证恢复；
- 灰色：没有数据或尚未检查。

颜色只表达证据和状态，不直接表达隐藏真相。点击节点显示平台原始信号、字段来源、关联原因、候选和检查记录。测试关系统一标记“测试拓扑”；没有真实关系时显示“未知”，不能为了画完整而补线。

### 10.4 动态处置路径

- 横向或纵向显示已经执行的步骤；
- 当前步骤突出，走过路径高亮；
- 未走分支保留为浅色并说明未执行原因；
- 每一步可展开查看输入证据、执行者、动作、结果和分支理由；
- 自动步骤和人工责任步骤使用不同形状；
- 中途恢复时直接连接到恢复验证；
- “证据不足”“禁止操作”“转专业组”和“失败接单”拥有明确终点。

### 10.5 演练成绩单

演练结束后展示系统实际结果与隔离答案的比较。盲测答案仅在此时揭示。

## 11. 角色与责任

- **AI 管理员**：查看故障目录、运行定向演示和盲测、比较模型/提示词/知识版本；不能代表现场授权危险操作；
- **最高管理员**：拥有 AI 管理员能力，可在演练结束后查看隔离答案、完整审计和失败详情；
- **现场、机房组长、接口人**：在正式工作台看到与其角色相关的模拟待办和反馈界面，但不能选择场景、查看隐藏答案或篡改演练时钟；
- **模拟器服务账号**：只允许向模拟接入口发送带 `simulation=true` 的信号；
- **评分器服务账号**：只在结束评分时读取隐藏答案。

演练环境中的人工动作也要记录角色和账号。演练结果不得混入真实生产指标、真实工单和真实资产变更。

## 12. 异常与失败处理

必须覆盖：

- 平台断开、降级、延迟、重复、乱序、权限不足和无效返回；
- OMS、BMC、NMS 和现场报告的完整 SN、机架位或端口冲突；
- 上游故障晚于下游信号到达；
- 两个独立故障同时出现；
- 一个故障影响多台设备或业务；
- 监控恢复但业务未恢复；
- 换模块、换线、换盘或重启后无改善；
- 夜间单人值班、无人及时复核和非紧急延后；
- 模型未配置、超时、格式错误、无证据判断或危险建议；
- 所有获准检查完成后仍证据不足。

合法结束状态：

1. 已确认故障并修复；
2. 已缩小范围并转交专业组；
3. 现场能力范围已完成但仍未解决；
4. 身份、权限或业务状态冲突，禁止操作；
5. 证据不足，需要补充数据；
6. 误报或无需现场操作；
7. 演练被人工终止。

## 13. 评分与 AI 提效指标

每次运行记录：

- Top-1、Top-3 是否包含真实故障；
- 设备、端口、模块和影响范围是否正确；
- 是否正确分派给网络、系统、动环、应用或现场；
- 是否误合并、漏关联或制造重复事件；
- 从首条信号到形成有效候选的逻辑时间；
- 自动完成的只读查询数；
- 减少的人工复制日志、查询身份和重复描述次数；
- 人工介入次数及其是否发生在责任节点；
- 无证据结论、越权动作和危险建议数；
- 恢复后是否同时完成监控验证、业务验证和人工确认。

系统不预设“提效百分比”。基线和真实模型必须在相同场景、相同输入、相同平台状态和相同人工反馈下比较。测试模型桩不计入 AI 增益。

## 14. 验证方案

### 14.1 单元与合同测试

- 隐藏真相不会进入平台事件、事故、提示词或角色接口；
- 信号实际经过统一入口并保持幂等；
- 逻辑时钟、暂停、继续、单步和跳转行为正确；
- 反馈驱动正确分支，中途恢复不会继续无意义操作；
- 角色权限在前后端同时生效；
- 历史运行不可被新版本覆盖。

### 14.2 场景回归

- 25 个故障全部可以完成定向演示和盲测；
- 每个场景至少验证一个正常分支和一个失败/无效分支；
- 网络模块、光纤、端口硬件和配置异常必须能够用不同后续证据区分；
- 多设备、双故障、迟到上游、身份冲突和恢复未验证有独立回归案例。

### 14.3 浏览器验收

- 管理员可运行、暂停、推进和终止演练；
- 普通角色不能触发场景或查看答案；
- 桌面和移动端可读；
- 拓扑与路径可通过键盘选择，并有非颜色状态说明；
- 页面显示真实接口返回和分析模式，不出现伪造 AI 状态。

## 15. 分阶段落地

### 第一阶段：演练引擎闭环

- 场景合同、隐藏真相隔离、运行状态机和逻辑时钟；
- 五类故障目录；
- 定向/盲测、三种推进方式；
- 平台逐条接入、人工暂停点、结果评分；
- 先打通网络光模块/光纤/端口这一条复杂黄金链。

### 第二阶段：25 个场景与动态路径

- 将现有日志和闭环测试整理为 25 个版本化场景；
- 为每个场景补充分支、失败结论、责任组和恢复验证；
- 建立完整回归集。

### 第三阶段：定位卡与影响路径视觉

- 使用内置测试资产验证物理定位、影响链和节点详情；
- 同一事故按业务网、带外管理网和应用服务路径分别展示，避免交叉线堆叠；
- 保持资产关系数据与视图解耦，后续可替换为 CMDB、OMS 和 NMS 真实关系；
- 大规模场景只显示与当前事故相关的子图，不渲染整座机房全部设备。

## 16. 完成标准

本功能只有同时满足以下条件才算完成：

1. 管理员可以从五类故障库触发具体故障或随机盲测；
2. 隐藏答案没有进入分析上下文；
3. 平台信号逐条经过现有真实接口和治理链；
4. 自动调查在人工责任点可靠暂停；
5. 人工反馈可以改变后续路径，中途恢复可以提前结束；
6. 物理定位卡和故障影响路径能展示位置、故障证据、影响、调查和恢复状态，且不补造未知链路；
7. 动态路径能够解释每一步的输入、动作、结果和分支；
8. 25 个具体场景均有定向演示、盲测和回归结果；
9. 普通角色不能触发模拟器或看到隐藏答案；
10. 成绩单如实区分规则基线、测试模型桩和真实模型；
11. 所有测试报告明确说明模拟结果不能证明真实生产准确率。
