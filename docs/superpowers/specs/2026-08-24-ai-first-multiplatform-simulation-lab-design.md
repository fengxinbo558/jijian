# AI 主动调查与多平台模拟接入实验室设计

> 日期：2026-08-24
>
> 状态：待用户最终复核
>
> 适用项目：机鉴 · IDC AI 故障调查台

## 1. 背景与问题

机鉴当前已经具备事件、证据链、规则与知识库、RAG 回放、现场处置卡、OMS 快照、完整 SN 核对、人工复核、CC 判断和模型适配入口。但是当前版本仍以人工粘贴、Webhook 和内置场景为主，真实 OMS、CMDB、BMC、动环、网络 NMS、交换机 syslog 和 Linux 监控尚未接通；主事件页面也没有形成真正的分角色工作台。

用户要求下一阶段必须同时满足四点：

1. **AI 是产品核心**：不是在固定工作流末尾追加一段 AI 摘要，而是由 AI 主动调用多个只读工具调查故障。
2. **真实作业提效**：尽量减少网络组、系统组、现场人员之间翻日志、重复描述、重复录入和反复确认。
3. **责任边界明确**：AI 可以自动收集、关联、分析和生成草稿，但不能决定断电、重启、换件、CC 执行或其他需要人承担责任的操作。
4. **全过程可审计**：无法读取模型不可见的内部隐式思维，但系统实际收到、调用、转换、引用、拦截和人工确认的内容必须可查看、可回放、可导出。

## 2. 产品定位

机鉴的核心定位调整为：

> **确定性数据与身份底座 + AI 主动故障调查 Agent + 人工责任决策与现场执行。**

动环、网络、BMC、Linux、应用、OMS、CMDB、知识库和现场反馈都是 Agent 可以使用的工具或证据来源。规则不替代 AI 调查，规则负责设备身份、安全门禁、数据契约、证据引用和危险动作阻断。

## 3. 目标与非目标

### 3.1 本阶段目标

- 增加独立的“平台接入实验室”，模拟六类真实平台。
- 模拟平台通过与未来真实平台相同的统一 HTTP 接口发送数据，不直接在前端伪造事件结果。
- 每个平台可以独立设置已连接、未连接、异常、延迟和无权限，实现部分接入与部分联动。
- 支持显式事故号、精确设备身份、资产拓扑加时间窗口三种确定性关联。
- 只有语义相似时，AI 只能提出“疑似相关”，不能自动合并事件或创造设备关系。
- AI Agent 可以自主选择和调用模拟平台的只读查询工具，动态更新竞争原因，并在证据足够、证据不足或达到预算时停止。
- 同一场景可以运行固定规则基线与真实模型 Agent，对比 AI 是否产生实际增益。
- 每个事件增加完整 Agent 调查回放；最高管理员可以查看脱敏的模型输入、结构化决策记录、工具调用、原始返回、候选变化、规则拦截和人工修正。
- 将现有角色重构为真正不同的工作台，并在服务端执行字段、操作和数据范围权限。
- 增强知识发布可信度与 SQLite 在线备份、恢复验证。

### 3.2 非目标

- 本阶段不连接未经授权的生产设备或客户真实平台。
- 不把测试模型桩、预设场景或规则规划器冒充成真实 AI。
- 不执行关机、重启、改配置、端口切换、工单发送、如流消息发送或硬件操作。
- 不展示或声称可以读取大模型不可见的私有逐字思维链。
- 不用 AI 猜测 SN、设备名、机架位、端口、IP、上下联和业务归属。
- 不把合成测试通过率称为真实生产故障定位准确率。

## 4. 总体架构

```text
动环/DCIM ───────┐
网络 NMS/syslog ─┤
BMC/Redfish ─────┤
Linux/应用日志 ──┼→ 统一接入网关 → 原始快照与来源状态
OMS/CMDB ────────┤                         ↓
现场反馈 ────────┘             标准化、身份解析与拓扑映射
                                              ↓
                                  事故关联与跨平台时间线
                                              ↓
                       ┌──────────────────────┴─────────────────────┐
                       │                                            │
                 固定规则基线                                AI 调查 Agent
                       │                              竞争原因 → 工具调用 → 更新
                       └──────────────────────┬─────────────────────┘
                                              ↓
                               证据账本、调查回放与对照评测
                                              ↓
                             分角色工作台、人工责任点与现场闭环
```

系统分为七个边界清晰的组件：

1. **模拟平台与连接状态**：生成平台原始数据，模拟连接、断开、延迟和错误。
2. **统一接入网关**：验证统一事件契约，保存不可变原始快照并返回真实接口响应。
3. **身份与拓扑解析器**：只使用外部字段、资产记录和人工确认建立确定性关系。
4. **事故关联器**：按事故号、精确身份、拓扑和时间窗口形成关联；AI 语义相似只生成待确认建议。
5. **AI 调查编排器**：管理调查目标、工具权限、轮次、预算、竞争原因和停止条件。
6. **证据与推理审计**：保存每一步输入、动作、输出、引用、拦截和人工修正。
7. **分角色工作台**：为现场、组长、接口人、AI 管理员和最高管理员返回不同内容与操作。

## 5. 统一平台事件契约

所有模拟平台和未来真实平台使用同一外层结构：

```json
{
  "source_system": "network_nms",
  "source_event_id": "NMS-20260824-001",
  "occurred_at": "2026-08-24T10:00:00+08:00",
  "received_at": "由服务端填写",
  "site": "BJYZ",
  "incident_key": "可选",
  "entity": {
    "sn": "可选但不得猜测",
    "device_name": "可选",
    "management_ip": "可选",
    "mac": "可选",
    "rack_position": "可选",
    "interface": "可选"
  },
  "signal_type": "link_flap",
  "severity": "critical",
  "summary": "端口反复抖动",
  "raw_payload": {},
  "simulation": true
}
```

要求：

- `source_system + source_event_id` 用于幂等去重。
- 原始数据完整保存，标准化字段不能覆盖原文。
- 字段必须记录来源：平台提供、资产映射、规则解析、人工确认或未知。
- 模拟数据始终标记 `simulation=true`，不得与真实数据混淆。
- 缺少身份时允许保存事件，但不得自动绑定具体设备或进入现场操作许可链。

## 6. 六类模拟平台

### 6.1 动环 / DCIM

可输入温度、湿度、漏水、烟雾、空调、单路/双路供电、区域、机房等级和受影响范围。只负责提供设施事实，不直接决定是否 CC；CC 仍由确定性矩阵和人工流程处理。

### 6.2 网络 NMS / syslog

可输入交换机、槽位、端口、上下联、链路状态、抖动次数、CRC、丢包、光功率、模块状态、协议邻居和原始 syslog。只读工具支持查询端口详情、对端、历史指标和同设备告警。

### 6.3 BMC / Redfish

可输入完整 SN、设备电源、SEL、双电源、风扇、温度、磁盘、内存、网卡和管理口状态。只读工具支持查询电源、硬件健康、SEL 和网卡链路。

### 6.4 Linux / 应用监控

可输入 journald、dmesg、内核、文件系统、进程、端口、服务、应用错误、指标和 Trace 摘要。只读工具支持查询时间窗日志、服务状态、资源趋势和相关错误。

### 6.5 OMS / CMDB

可输入工单号、完整 SN、机架位、设备名、业务状态、是否从重装发起、操作许可、资产关系、交换机端口映射和工单时效。模拟平台只提供快照，不替代真实资产审批。

### 6.6 现场反馈

可输入现场看到的完整 SN、UID、机架位、指示灯、声音、气味、温度、线缆、光功率和操作结果。人工输入与平台自动数据分开标记。

每个平台包含两种输入方式：面向普通用户的字段表单，以及面向管理员的原始 JSON 编辑器。

## 7. 连接状态与部分联动

每个平台独立维护以下状态：

- `connected`：可以发送事件并接受只读查询。
- `disconnected`：没有数据，Agent 必须显示证据缺口。
- `degraded`：部分字段缺失或响应不稳定。
- `delayed`：按配置延迟返回，用于测试超时和乱序事件。
- `permission_denied`：平台可见但查询权限不足。
- `invalid_payload`：返回结构错误，用于验证契约校验。

断开一个平台不能阻塞其他平台接入。Agent 必须基于现有证据继续调查，并明确说明缺少哪些平台、结论因此受到什么限制。

## 8. 确定性身份与事故关联

关联优先级固定为：

1. **显式事故号**：不同平台提供相同 `incident_key` 时自动进入同一事故，但只证明属于同一外部事故，不自动证明共同根因。
2. **精确设备身份**：完整 SN、不可变设备 ID 或经 CMDB 确认的映射完全一致时关联同一设备。
3. **真实拓扑加时间窗口**：CMDB 明确记录交换机端口连接服务器，且信号在配置时间窗内出现时形成可解释的连锁关系。
4. **AI 语义建议**：只有文本和时序相似但缺少确定性关系时，生成待人工确认的关联建议，不能自动合并。

身份冲突时系统停止自动关联，保留两个来源的原值并要求接口人或资产负责人确认。AI 不得选择“更像真的”一个值覆盖另一个。

## 9. AI 主动调查 Agent

### 9.1 调查循环

```text
观察证据
  → 形成多个竞争原因
  → 选择信息增益最高的只读工具
  → 执行工具并保存原始返回
  → 更新、削弱、排除或保留原因
  → 判断继续、停止、证据不足或转人工
```

每轮模型必须返回结构化对象：

- 当前事实和证据 ID；
- 竞争原因及支持证据、反证和缺失证据；
- 下一项工具、查询对象和可审计的任务说明；
- 本轮工具结果如何改变候选；
- 是否停止以及停止原因。

模型不能直接调用任意 URL 或执行任意命令，只能从工具注册表选择获准的只读工具。编排器负责真正执行、超时、重试、参数校验和审计。

### 9.2 停止条件

- 已有确定性工具结果确认故障范围；
- 下一步必须由人现场检查或批准；
- 关键平台未连接，继续调查不会增加信息；
- 证据互相矛盾，需要人工确认身份或上下文；
- 达到最大轮次、时间或调用预算；
- 模型连续产生无证据、无效或越权输出。

### 9.3 双轨对照

- **固定基线**：规则与知识库，可重复、可兜底，明确标记为非 AI。
- **真实 AI Agent**：只有真实模型接口连通并完成健康检查后才能运行。
- **测试模型桩**：只用于验证协议和自动测试，页面必须标记“测试桩”，不能计入 AI 增益。

同一场景支持并排查看基线与 Agent 的调查步数、工具调用、Top-3 候选、证据缺口、危险建议和停止结论。

## 10. AI 调查回放与最高管理员审计

### 10.1 三种查看层级

- **简洁模式**：展示 AI 做了什么、为什么做、得到什么和下一步。
- **完整回放**：展示全部平台输入、工具调用、证据、候选变化和人工决策。
- **原始审计**：最高管理员查看脱敏的模型输入输出、提示词、知识、厂商、参数、校验和规则拦截。

### 10.2 每一步记录

- 调查轮次、开始和结束时间；
- 当时可用的证据与事实；
- 模型厂商、模型、提示词和知识版本；
- 结构化任务说明；
- 工具名、脱敏参数、返回状态、原始快照和证据 ID；
- 调用前后的候选变化；
- 无证据内容、越权动作和格式错误的拦截记录；
- 人工确认、驳回、修正和责任人；
- 调用次数、耗时和可用时的成本统计。

系统不声称读取模型不可见的私有逐字思维。可审计内容来自 Agent 每轮显式输出、工具真实返回、系统规则和人工记录。

### 10.3 原始数据临时查看

最高管理员默认看到完整结构化过程，但敏感字段仍脱敏。查看未脱敏原始日志或模型输入需要：

1. 点击“临时查看原始数据”；
2. 填写查看原因；
3. 再次确认；
4. 获得短时访问；
5. 保存查看人、时间、事件、字段范围和原因。

## 11. AI 与人的责任分层

| 等级 | 范围 | AI 权限 | 人的责任 |
|---|---|---|---|
| L0 | 数据接收、字段提取、时间线 | 自动完成 | 无须逐条确认 |
| L1 | 网络、BMC、系统、动环、OMS 只读查询 | 自动调用 | 可回放和驳回 |
| L2 | 原因排序、反证、下一步建议 | 自动生成 | 接口人判断是否采纳 |
| L3 | 如流消息、工单反馈、接单详情草稿 | 自动生成，不自动发送 | 人确认后提交 |
| L4 | 重启、关机、换件、拔线、改配置 | 禁止执行和批准 | 有权限的人决策并执行 |
| L5 | CC、核心机房、业务迁移、紧急断电 | 整理证据和提醒 | 负责人执行既有流程 |

新增 AI 能力前必须先标记 L0—L5。L4、L5 不因模型能力提升而自动放权。

## 12. 分角色工作台与权限

### 12.1 角色

- **现场人员**：待办、完整 SN、机架位、UID、操作许可、现场步骤和结果反馈。
- **机房组长**：人员与任务队列、时效、远程复核、高风险操作和现场协调。
- **系统/网络接口人**：技术证据、竞争原因、只读工具结果、下一步调查、许可和沟通草稿。
- **AI 管理员**：知识、提示词、模型厂商、评测、发布和回滚。
- **最高管理员/审计管理员**：跨角色全链路、AI 调查审计、权限审计、原始数据临时查看和恢复操作。

### 12.2 服务端约束

- 正式模式不允许浏览器自由切换角色和账号。
- 当前角色切换器仅在显式演示模式中显示。
- 角色来自可信身份系统、签名会话或后续 OMS/企业统一身份。
- 操作人与复核人必须是两个不可伪造的账号，而不是两个不同字符串。
- API 按角色裁剪字段和数据范围，不能只靠前端隐藏按钮。
- 所有查看、授权、发布、回滚和人工覆盖均进入追加式审计。

## 13. 知识可信度与发布

每条经验保留多个条件化版本，不因一次处理不同就删除旧经验。知识卡新增：

- 来源、原始案例或官方文档；
- 适用设备、型号、软件/固件版本和环境；
- 支持信号、反证、分支和停止条件；
- 证据等级、审核人、负责人和审核时间；
- 失效日期或复审日期；
- 正例、反例和不得命中的测试案例；
- 与其他版本的差异和共存条件。

发布验证分为：

1. 结构检查；
2. 历史场景回归；
3. 反例与危险建议测试；
4. 专业人员审核；
5. 上线前最终确认；
6. 可回滚且不重写历史事件。

“字段完整”只能显示“结构检查通过”，不能显示“知识正确”。真实知识正确性必须由来源、案例、反例和专业审核共同支撑。

## 14. 页面设计

主导航新增“接入实验室”，不与“模拟案例”混在一起。

### 14.1 接入实验室

- 六张平台卡：连接状态、最近事件、发送数量和错误数量。
- 平台详情：字段表单、原始 JSON、连接故障模拟和只读工具返回配置。
- 拓扑与资产：设备、端口、服务器、机架位和业务关系的确定性测试数据。
- 场景编排：按时间顺序发送多个平台事件，也可逐条手动发送。
- 投递日志：请求地址、状态码、响应、事件 ID、事故 ID 和关联原因。
- 预设连锁场景：网络模块故障导致服务器失联和应用超时、制冷异常导致多机告警、供电异常引发 BMC 与系统事件等。

### 14.2 AI 调查区

- 左侧：跨平台事件时间线。
- 中间：Agent 调查轮次和工具调用。
- 右侧：竞争原因、支持证据、反证、缺失证据和当前结论等级。
- 顶部：固定基线与真实 Agent 对照；模型未连通时 AI 一栏明确显示不可运行。
- 每个结论可以点击回到证据、平台原始数据和字段来源。

### 14.3 角色视图

同一事故保留一个底层档案，但按角色展示不同首页、字段和主要操作。最高管理员可进入“AI 推理审计”，其他角色只能查看完成其职责所需的内容。

## 15. 异常处理

- 重复事件：按来源事件 ID 幂等，保存重复投递审计但不重复建事故。
- 迟到和乱序：保留事件发生时间与接收时间，重建时间线但不改写原始记录。
- 身份冲突：停止自动绑定，保留冲突并请求人工确认。
- 平台断开：继续使用其他来源，明确证据缺口。
- 工具超时：记录超时、有限重试，不能让模型猜测返回。
- 模型未配置：只运行固定基线，AI 状态显示未运行。
- 模型格式错误或无证据：硬校验失败，降级到基线并记录原因。
- 知识不足：显示覆盖不足，不调用常识填补成确认结论。
- 权限不足：工具返回无权限，Agent 不得绕过或更换未授权数据源。
- 高风险建议：直接拦截并进入审计，不展示为可执行步骤。

## 16. 数据库备份与恢复

当前阶段继续使用 SQLite，但增加：

- 使用 SQLite 在线备份 API 创建一致性快照，不能简单复制正在写入的数据库文件。
- 每日自动备份，并在知识/提示词发布前创建备份。
- 默认保留最近 7 个每日备份和最近 10 个发布前备份，后续可配置。
- 备份包含事件、证据、知识、提示词、调查轨迹、平台配置、OMS 快照和审计记录。
- 模型密钥不进入数据库备份，继续由部署环境或密钥系统管理。
- 管理员可以执行恢复演练，但真实恢复需要最高管理员确认并完整审计。
- 自动测试必须把备份恢复到临时数据库并验证关键记录数量与哈希。

进入多用户试点后再评估 PostgreSQL、对象存储和主备复制；本阶段不把单机备份宣传成高可用集群。

## 17. 测试与验收

### 17.1 功能验收

1. 六类模拟平台都能通过统一接口发送事件。
2. 任一平台断开时，其他平台仍可形成事故，页面显示证据缺口。
3. 相同事故号自动进入同一事故，但不自动宣称共同根因。
4. 无事故号时，精确 SN 或真实拓扑加时间窗口可形成可解释关联。
5. 只有语义相似时不能自动合并，必须进入待确认建议。
6. 交换机模块/端口故障可以串联服务器失联、系统重试和应用超时。
7. Agent 可以经过多轮只读工具调用更新竞争原因并提前停止。
8. 工具失败、模型失败和知识不足都必须诚实降级。
9. 固定基线与真实 Agent 可以运行同一隐藏真值场景并对照。
10. 五种角色看到不同工作台、字段和操作，服务端拒绝越权。
11. 最高管理员可以回放完整结构化调查；查看未脱敏原文必须二次确认并审计。
12. SQLite 备份可恢复到临时环境且关键记录一致。

### 17.2 AI 增益指标

- Top-3 候选包含隐藏真值的比例；
- 从初始告警到缩小故障范围的调查轮次；
- 无效工具调用数；
- AI 正确停止和正确放弃判断的比例；
- 无证据断言率；
- 危险建议率，目标为 0；
- 相比固定基线减少的人工查询和沟通次数；
- 平均故障确认时间和现场到达前准备完成度。

合成测试只证明协议、流程、安全边界和预设场景表现。生产准确率必须使用脱敏真实历史案例或试点事件，由系统/网络/现场专业人员共同给出隐藏真值。

### 17.3 真实试点目标

当获得客户授权和接口后，首个试点目标是：

> 至少 70% 的试点故障原始数据不需要人工复制粘贴，即可进入机鉴事故档案。

该指标按平台和故障类型分别统计，不能用模拟平台数据代替。

## 18. 实施分期

### 第一阶段：可运行的模拟接入与审计骨架

- 统一事件契约和六类模拟平台；
- 独立连接状态与部分联动；
- 确定性身份、拓扑和关联等级；
- 平台接入实验室页面；
- Agent 工具注册表、调查轮次和审计数据结构；
- 固定基线与测试模型桩，真实模型未连接时不冒充 AI；
- 分角色页面骨架与最高管理员审计；
- SQLite 在线备份与恢复测试。

### 第二阶段：真实模型 Agent

- 接通本地模型或合作厂商 OpenAI 兼容接口；
- 实现受限工具调用循环、输出校验、预算和降级；
- 运行基线与 Agent 隐藏真值对照；
- 根据结果决定模型、提示词和知识策略。

### 第三阶段：逐个替换模拟连接器

- 优先接入一条真实 Linux/系统或网络链路；
- 接入 OMS/CMDB 只读身份与拓扑；
- 再接 BMC、动环和企业通知；
- 每替换一个模拟连接器，都复用同一事件契约、工具接口、调查回放和评测集。

## 19. 最终约束

1. AI 尽可能多承担信息工作，但不承担真实操作责任。
2. 设备身份、资产关系和操作权限不能由模型猜测。
3. 没有真实模型时不展示“AI 已完成调查”。
4. 所有系统实际执行的调查步骤都可追溯，模型不可见的内部思维不作虚假承诺。
5. 同一事故只有一个底层事实档案，但不同角色看到不同工作台和数据范围。
6. 模拟平台必须走未来真实平台复用的接口，不能只在页面生成结果。
7. 先证明一条真实闭环和 AI 增益，再继续扩大平台范围。
