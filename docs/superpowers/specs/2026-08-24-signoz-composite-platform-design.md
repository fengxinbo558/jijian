# 机鉴第三版：SigNoz 复合底座设计

> 状态：用户已授权按推荐直接搭建
> 日期：2026-08-24
> 决策：以 SigNoz Community 作为遥测数据底座，以 HolmesGPT 作为可选只读 AI 调查服务，保留机鉴作为 IDC 领域控制层

## 1. 目标

第三版把当前“人工提交一段数据后分析”的原型扩展成可以连接真实监控底座的产品骨架。产品必须让用户清楚看到：数据从哪里来、系统查询了什么、哪些是事实、哪些是候选、AI 调用了哪些只读工具，以及为什么形成当前处置建议。

本轮不把 SigNoz、HolmesGPT、NetBox 或 OMS 的全部界面复制进机鉴，也不把多个大型开源仓库合并成一个难以升级的代码库。外部能力通过稳定 API、Webhook、OpenTelemetry 和可选服务连接；机鉴只负责 IDC 特有的调查、身份核验、现场操作、安全门、接单闭环和经验资产。

## 2. 选型结论

### 2.1 主底座：SigNoz Community

选择理由：

- OpenTelemetry 原生，能够统一接收日志、指标和链路；
- 官方提供 Linux 裸机部署和主机监控，能按主机查看 CPU、内存、磁盘、网络、日志和链路；
- Community 核心代码为 MIT Expat，企业目录单独授权，产品边界相对清楚；
- 提供日志和指标查询 API，适合由机鉴按事故时间窗、主机名、SN 映射或设备属性自动取证；
- 已有官方 MCP 服务，便于后续 AI 通过受控工具查询 SigNoz，而不是由模型编造查询结果。

### 2.2 AI 调查层：HolmesGPT（可选服务）

选择理由：

- Apache-2.0；
- 支持 VM、裸机、云和容器，不强制 Kubernetes；
- 提供带 API Key 的 HTTP `/api/chat`、健康检查和工具调用记录；
- 能连接 Prometheus、ClickHouse、Zabbix、数据库、REST API 和 MCP；
- 适合作为只读调查执行器，但不承担 IDC 操作授权。

### 2.3 参考但不作为主运行依赖

- Keep：借鉴告警去重、聚合和事件编排，不在本轮部署第二套事件平台。
- NetBox：借鉴设备、机架、接口和线缆模型；客户已有 OMS/CMDB 时优先适配现有资产系统。
- HyperDX：保留为 MIT 备选；本轮因裸机主机监控不如 SigNoz 与当前目标直接而不采用。
- OpenObserve：日志能力和单体部署优秀，但 AGPL 会增加产品化边界判断，本轮不采用。

## 3. 总体架构

```text
Linux journald/文件日志 ─┐

BMC/Redfish 事件 ───────┤              │
应用运行日志/链路 ──────┘              ▼
                                  SigNoz Community
                              日志、指标、告警、时间窗查询
                                          │
                       只读查询 API / SigNoz MCP
                                          ▼
                    ┌──────────── 机鉴调查控制层 ────────────┐
                    │ 数据来源登记、证据标准化、事件关联       │
                    │ 完整 SN/机架位、候选原因、反证和缺失证据 │
                    │ 现场安全门、操作会话、接单、经验分支     │
                    └───────────────┬────────────────────────┘

                         只读工具调查＋工具调用审计
```

## 4. 模块边界

### 4.1 数据来源登记

机鉴维护来源清单而不是假装采集器已经连接。每个来源显示：用途、连接方式、运行状态、最近检查时间、是否自动取证和数据是否离开本地。

首批来源：

- 人工日志：用户上传或粘贴；
- 现场上报：现场观察和身份信息；
- 通用监控告警：外部平台 Webhook；
- SigNoz：真实日志、指标和告警底座；
- HolmesGPT：可选 AI 调查服务。

SNMP、Redfish、NetBox/OMS 在数据模型中登记为可扩展来源，但没有真实连接配置时必须显示“尚未连接”。

### 4.2 SigNoz 适配器

适配器只负责：

- 调用健康接口判断服务是否可达；
- 使用 API Key 查询指定时间窗内的日志和指标；
- 接收 SigNoz 告警 Webhook 并转换成机鉴统一输入；
- 把查询请求、响应摘要、耗时和错误写入调查轨迹；
- 对返回记录做数量和大小限制，避免把海量原始日志直接交给模型。

适配器不修改 SigNoz 告警规则，不删除数据，不改变保留期。

### 4.3 HolmesGPT 适配器

适配器使用带认证的 HTTP API，发送当前事件摘要、事实、候选、时间窗和允许使用的数据源。返回内容必须保存工具调用记录，并经过机鉴既有证据校验：

- 没有引用现有事实或工具结果的结论不能升级为已确认；
- HolmesGPT 不能写入设备身份、电源权限或操作许可；
- 默认只启用只读数据源；
- HolmesGPT 不可用时，规则＋知识＋SigNoz 查询仍继续工作。

### 4.4 IDC 领域控制层

继续由机鉴独立实现：

- 统一事件和多设备事故；
- 完整 SN、机架位、设备名和 UID 核验；
- 是否从重装中发起、是否允许断电和接口人确认；
- 开始操作、确认操作、现场执行、结束操作；
- 成功/失败接单、故障详情、详细反馈、上线/下线备件 SN；
- 三网验证、重复派单识别、设备历史和经验分支；
- CC 只在最开始提醒拨打现有电话，不扩展固定通报流程。

## 5. 真实故障数据流

```text
监控告警或现场发现异常
  → 建立事件并记录来源
  → 用设备身份和时间窗查询 SigNoz
  → 提取日志事实和指标异常
  → 规则与知识库生成多个候选
  → 可选 HolmesGPT 调用只读工具补充调查
  → 证据校验、反证检查和结论分级
  → 判断远程继续调查或转现场
  → 现场身份/电源安全门
  → 操作与验证
  → 成功或失败接单
  → 处理结果进入设备历史和经验分支
```

任一阶段已经恢复，就在该阶段停止继续排查；不得把固定检查链一条路执行到底。

## 6. 界面与用语

页面只保留面向使用者的明白话：

- “接入”改为“分析真实故障”；
- “演练”改为“查看模拟案例”；
- “接入故障数据”改为“你现在手里有什么？”；
- 三个选项为“我有一份日志”“我在现场发现了异常”“监控系统发现了异常”；
- JSON 和 Webhook 配置移到“数据来源”，不与现场操作入口混在一起。

事件详情第一屏增加“数据从哪来”状态条，依次显示收到告警、查询日志/指标、规则与知识判断、AI 补充调查、人工确认。每一步显示成功、未连接、等待或失败；点击后查看请求依据和证据，不展示模型私有逐字思维链。

视觉继续使用 IDC 运行台语汇：设备标签、信号链、冷灰底、墨蓝结构、青色确认、橙色待验证、红色只用于停止操作。标志性元素为“信号母线”，让用户从一条真实故障的入口一路看到证据和处置，而不是只看到最终答案。

## 7. 配置与安全

新配置全部使用环境变量：

- `IDCAI_SIGNOZ_URL`、`IDCAI_SIGNOZ_API_KEY`；
- `IDCAI_HOLMES_URL`、`IDCAI_HOLMES_API_KEY`、`IDCAI_HOLMES_MODEL`；
- 单次查询时间窗、最大记录数和最大响应字节数。

默认仍监听本机，默认不连接外部服务。服务 URL 未配置时只显示“尚未连接”。所有 API Key 不写入数据库、页面或日志；查询错误只保存脱敏摘要。生产部署需要 HTTPS、内网访问控制和独立只读账户。

## 8. 降级与错误

- SigNoz 未配置：保留人工日志、现场上报和通用告警，明确显示没有自动取证。
- SigNoz 查询失败：事件继续存在，轨迹记录失败原因和重试建议，不生成伪造证据。
- 查询结果过多：服务器端限制时间窗和条数，只保留命中记录及统计摘要。
- HolmesGPT 未配置或超时：使用规则＋知识＋SigNoz 证据，不显示“AI 已调查”。
- 身份不一致：停止现场操作，要求接口人确认，不允许 AI 决定。
- 重复自动派单：关联同一设备未解决历史事件，提示上次失败结论和已做检查。

## 9. 本轮实现范围

本轮交付：

- 数据来源状态页和明白话入口；
- SigNoz 健康检查、日志/指标查询客户端和告警 Webhook 契约；
- HolmesGPT 健康检查和 `/api/chat` 调查客户端；
- 真实/模拟来源在事件链中的明显区分；
- 事件详情中的“数据从哪来”和自动调查步骤；
- OpenTelemetry Collector 的 Linux 日志/主机指标示例配置；
- 连接器的单元测试、API 测试和无服务降级测试。

本轮不下载或修改 SigNoz、HolmesGPT 的全部源码，不承诺当前电脑没有 Docker 时能同时启动两个大型服务，不连接真实 OMS、如流、BMC 或交换机，也不执行任何基础设施写操作。

## 10. 验收标准

- 首页不再出现含糊的“事件接入”；
- 用户能区分真实故障分析和模拟案例；
- 数据来源页能如实显示人工入口、SigNoz 和 HolmesGPT 是否连接；
- 配置假的或不可达的服务地址时，页面显示失败而不是已连接；
- SigNoz 告警 Webhook 能创建统一事件并保留来源；
- SigNoz 查询返回的证据带查询时间窗和来源，不被冒充为人工输入；
- HolmesGPT 输出保存工具调用摘要，未经证据支持的结论不能成为已确认根因；
- 未配置任何外部服务时，现有功能和测试仍可运行；
- 桌面和手机页面可使用，键盘焦点可见；
- 完整自动测试、评测和浏览器烟雾测试通过后才能宣称完成。
