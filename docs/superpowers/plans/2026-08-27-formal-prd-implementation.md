# 正式 PRD 编制实施计划

**设计依据：** `docs/superpowers/specs/2026-08-27-prd-document-design.md`  
**正式产物：** `docs/product/02-机鉴PRD产品需求文档.md` 与同名 `.docx`

## 任务 1：建立需求事实清单

- 从 README、现有设计说明、页面、API、数据结构和测试中提取模块、角色、流程、状态、字段和异常；
- 每项能力标注事实状态，不将模拟、接口骨架或测试模型桩写成生产能力；
- 核对立项报告中的范围、非目标和安全边界。

## 任务 2：编写 Markdown 正文与附录

- 按已确认的正文十六章和附录 A-H 编写；
- 使用真实三级标题，适配飞书导入后的上下级目录；
- 为关键需求分配稳定编号、优先级、能力状态和验收条件；
- 明确正常路径、异常路径、停止条件、责任人和降级方式。

## 任务 3：内容一致性审计

- 扫描占位符、标题跳级、重复段落和无法测试的模糊表述；
- 核对必填字段、角色权限、事故关联、安全门禁和 CC 边界；
- 将需求编号与当前自动测试、浏览器验证、沙盒验证或真实试点缺口映射。

## 任务 4：生成正式 Word 文档

- 使用 `compact_reference_guide` 版式预设；
- 使用 `memo_masthead` 首屏模式并延续机鉴深蓝、青绿色；
- 通过真实 Heading 1/2/3、真实列表和精确 DXA 表格几何保留目录层级；
- 使用封面、文档信息、静态目录、页眉页脚和变更记录。

## 任务 5：渲染与修订

- 将 Word 渲染为逐页 PNG；
- 检查全部页面的中文字体、标题、分页、表格、页眉和页脚；
- 修复缺字、溢出、断裂、留白异常和密度问题后重新渲染。

## 任务 6：最终验证与提交

- 运行无障碍、标题层级、章节、表格几何和脚本语法审计；
- 检查正文十六章、附录 A-H、关键字段和事实状态是否齐全；
- 仅提交本次 PRD 相关文件，不混入工作区其他改动。
