# 故障中心界面重构实施计划

日期：2026-08-26

设计依据：`docs/superpowers/specs/2026-08-25-incident-center-ui-redesign.md`

## 实施原则

- 保留事件、调查、现场操作、管理、接入、治理和演练功能；
- 先改变前端信息架构，不修改事故数据模型和 AI 调查算法；
- 默认真实事件队列不显示模拟数据；
- 页面外壳固定在视口内，列表与详情内容独立滚动；
- 详情按“概览、AI分析与证据、处置协同、原始记录”分区；
- 角色差异继续由服务端权限约束，前端只负责正确呈现；
- 每个实施阶段完成后运行语法或浏览器检查。

## 任务一：重构故障中心页面骨架

### 文件

- 修改：`web/index.html`
- 修改：`web/styles.css`

### 内容

1. 将三栏结构改为“功能栏 + 故障中心”；
2. 新增全宽列表视图和独立详情视图；
3. 新增返回列表、上一条、下一条和详情页签结构；
4. 桌面端外壳固定在视口高度内；
5. 移动端保留紧凑导航和单页详情。

### 验收

- 页面不再同时永久展示 350px 队列和详情；
- 列表和详情可以互相切换；
- 其他功能对话框仍能从左侧功能栏打开。

## 任务二：重写事件队列渲染和筛选

### 文件

- 修改：`web/app.js`
- 修改：`web/styles.css`

### 内容

1. 新增进行中、待处理、调查中、等待人工、已恢复和模拟演练分区；
2. 默认过滤模拟数据；
3. 新增严重度和专业组筛选；
4. 将大卡片改为高密度作业行；
5. 每行显示设备身份、位置、责任专业、下一步和更新时间；
6. 保存筛选、滚动和选中状态。

### 验收

- 1500×980 一屏可见至少八条紧凑事件行；
- 模拟数据只在模拟演练页签出现；
- 搜索、状态、严重度和专业组筛选共同生效。

## 任务三：重组故障详情

### 文件

- 修改：`web/app.js`
- 修改：`web/styles.css`

### 内容

1. 顶部固定呈现标题、状态、完整 SN、机架位、结论和下一步；
2. 新增事件状态轨道；
3. 将原详情拆入四个页签；
4. 页面只滚动当前页签内容；
5. 保留 CC 判断、数据路径、证据链、现场卡、沟通摘要、状态动作和原始输入；
6. 为现场、接口人和管理员设置合适的默认页签。

### 验收

- 详情首屏能回答故障对象、当前判断和下一动作；
- 证据链和原始日志不再与处置内容同时全部展开；
- 原有功能均有明确入口。

## 任务四：交互、历史和可访问性

### 文件

- 修改：`web/app.js`
- 修改：`web/styles.css`

### 内容

1. 列表与详情切换写入浏览器历史；
2. 返回时恢复筛选和滚动位置；
3. 支持上一条、下一条和键盘焦点；
4. 页签维护 `aria-selected` 和面板可见性；
5. 补齐小屏布局和减少动画设置。

### 验收

- 浏览器前进和后退不会丢失当前事件；
- 键盘可打开事件、切换页签和返回列表；
- 390px 宽度无页面级横向溢出。

## 任务五：自动化回归与视觉验收

### 文件

- 修改：`scripts/browser_smoke.cjs`
- 修改：`scripts/browser_smoke.py`
- 新增：`scripts/incident_center_browser_smoke.cjs`
- 更新：`reports/browser-desktop.png`
- 更新：`reports/browser-mobile.png`

### 内容

1. 调整既有浏览器脚本以适配列表先行和详情页签；
2. 新增专门的故障中心流程检查；
3. 检查默认模拟隔离、筛选、详情切换、页签和返回状态；
4. 检查桌面与移动截图、控制台错误和页面溢出；
5. 运行全量单元测试和既有演练/治理浏览器回归。

### 验收

- JavaScript 语法检查通过；
- 全量 Python 单元测试通过；
- 故障中心和既有浏览器流程通过；
- 桌面端截图不再形成超长页面；
- 移动端能从列表进入详情并返回。
