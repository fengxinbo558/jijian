# 交互式故障演练台实施计划

日期：2026-08-25

设计依据：`docs/superpowers/specs/2026-08-25-interactive-fault-drill-design.md`

## 实施原则

- 演练信号必须通过现有统一平台接入口，不在前端伪造分析结果；
- 隐藏真相与运行数据物理分表、接口隔离，运行结束前不返回；
- 人工反馈驱动分支，中途恢复立即转入恢复验证；
- 只为当前事故展示物理定位卡和影响路径，不绘制完整机房；
- 现有真实故障、告警治理、接入实验室、RAG、角色和现场操作功能不得丢失；
- 新功能先通过服务测试，再做页面和浏览器验收。

## 任务一：演练数据结构与25个故障目录

### 文件

- 新增：`data/drills/fault_catalog.json`
- 修改：`idcops/store.py`
- 新增：`idcops/drills.py`
- 新增：`tests/test_drills.py`

### 验收

1. 五类故障各5个，共25个；
2. 每个场景具有可见症状、平台信号、位置、影响路径、人工节点、恢复条件和评分规则；
3. 隐藏真相存入独立表，不出现在目录公开结构；
4. 场景版本和历史运行不可变。

## 任务二：运行状态机与真实信号接入

### 文件

- 修改：`idcops/drills.py`
- 修改：`idcops/service.py`
- 扩展：`tests/test_drills.py`

### 验收

1. 支持定向演示和随机盲测；
2. 支持单步、自动推进到暂停和跳到下一人工节点；
3. 信号逐条调用现有 `ingest_platform_event`；
4. 保存真实接口响应、告警和事故关系；
5. 人工节点暂停，结构化反馈决定分支；
6. 支持终止、失败、证据不足、转专业组和恢复验证；
7. 运行中任何普通返回不包含隐藏答案。

## 任务三：动态维修路径与成绩单

### 文件

- 修改：`idcops/drills.py`
- 扩展：`tests/test_drills.py`

### 验收

1. 网络端口抖动黄金链可区分配置、模块、光纤、端口和对端问题；
2. 换件恢复时不继续执行后续步骤；
3. 换件无效时生成新证据并继续调查；
4. 监控恢复和业务验证是独立门禁；
5. 完成后才返回隐藏真相与实际结果对比；
6. 记录定位、分派、误合并、重复、人工次数和安全违规指标。

## 任务四：API与角色权限

### 文件

- 修改：`idcops/auth.py`
- 修改：`idcops/server.py`
- 修改：`idcops/views.py`
- 新增：`tests/test_drill_api.py`

### 验收

1. AI管理员和最高管理员可查看目录、启动和控制演练；
2. 其他角色不能触发演练、读取场景ID或查看答案；
3. 运行事件仍按原有角色规则投影；
4. 答案只在完成或终止后向最高管理员或本次AI管理员操作者开放；
5. 所有操作记录账号、角色和时间。

## 任务五：故障演练页面

### 文件

- 修改：`web/index.html`
- 修改：`web/app.js`
- 修改：`web/styles.css`

### 验收

1. 管理角色左侧出现“故障演练”；
2. 五类故障卡可筛选，盲测只选择范围；
3. 提供单步、自动到暂停、跳到人工节点、终止和重开；
4. 显示平台信号、当前分析、人工反馈和运行模式；
5. 显示物理定位卡；
6. 影响路径按业务网、带外管理网或应用路径单独呈现；
7. 动态维修路径显示已走、当前、未走和结束节点；
8. 完成后显示成绩单，运行中不泄露答案；
9. 不影响现有页面与角色切换。

### 文件

### 验收

1. 25个故障可启动并至少形成一次真实平台输入；
2. 网络黄金链覆盖模块恢复、模块无效转光纤、换线恢复和升级处理；
3. 盲测运行中没有答案泄漏；
4. 无模型时明确显示规则与知识基线；
5. 桌面和移动端页面可读；
6. 非管理角色按钮隐藏且服务端返回403；
7. 全量单元测试、三套既有评测、新演练评测、浏览器烟测和差异检查全部通过。
