# 现场优先的故障详情与演练台实施计划

日期：2026-08-26  
设计依据：`docs/superpowers/specs/2026-08-26-field-first-incident-and-drill-layout-design.md`

## 实施边界

- 不修改事故、调查、知识库、RAG、现场操作和演练的数据模型；
- 不删除现有功能，只调整首屏摘要、分区入口和演练目录选择方式；
- 新增的错误状态只反映真实接口结果，不用占位数据掩盖失败；
- 高风险操作权限继续由服务端控制。

## 任务一：演练目录加载状态

### 修改文件

- `web/index.html`
- `web/app.js`
- `web/styles.css`

### 实施内容

1. 为演练状态增加 `loading`、`error` 和 `ready`；
2. 打开演练台时先显示加载提示；
3. 请求失败时显示失败原因和“重新加载”；
4. 成功后渲染五个分类及每类数量；
5. 空分类显示明确空状态，不再渲染空白下拉框。

### 验收

- 服务正常时显示 5 个分类、25 个场景；
- 服务不可达或返回错误时可见错误原因；
- 点击重新加载会再次发起目录和演练记录请求。

## 任务二：演练台信息架构

### 修改文件

- `web/index.html`
- `web/app.js`
- `web/styles.css`

### 实施内容

1. 分类改为横向标签，场景改为直接可见列表；
2. 保留定向/盲测与三种推进方式，但压缩成模式栏；
3. 当前场景摘要与触发按钮进入右侧首屏；
4. 运行过程改为五阶段进度条与当前动作卡；
5. 完整物理定位、影响路径、信号链、结果和历史记录放入可展开分区；
6. 现有 API 和表单提交字段保持不变。

### 验收

- 选择分类和场景无需打开下拉框；
- 启动、推进、人工反馈、终止和揭晓答案均可用；
- 完整演练记录仍可访问。

## 任务三：故障详情现场作业舱

### 修改文件

- `web/app.js`
- `web/styles.css`

### 实施内容

1. 顶部设备身份条紧凑展示完整 SN、机架位、设备名、责任组和状态；
2. 首屏三列展示“AI 当前判断与下一步”“关键证据”“协同状态”；
3. 状态轨道压缩为当前阶段提示，不增加页面高度；
4. 分区扩展为处置步骤、AI 推导与证据、沟通记录、原始日志和审计记录；
5. 复用原有内容组件，避免信息重复和数据分叉；
6. 不同角色设置符合职责的默认分区。

### 验收

- 1440×900 首屏无需页面级滚动即可看到身份、判断、风险、下一步、关键证据和分区入口；
- 现场人员默认看到处置步骤；
- 管理员默认看到 AI 推导与证据；
- 所有旧详情内容都有明确入口。

## 任务四：浏览器自动化与回归

### 修改文件

- `scripts/incident_center_browser_smoke.cjs`
- `scripts/drill_browser_smoke.mjs`
- 必要时新增专用浏览器测试脚本

### 实施内容

1. 校验目录加载、分类计数、场景切换和重试入口；
2. 校验定向演练与盲测完整流程；
3. 校验现场、接口人、组长和管理员默认分区；
4. 校验桌面和手机无页面级横向溢出；
5. 检查浏览器控制台错误；
6. 运行全量 Python 单元测试与既有浏览器回归。

### 验收

- JavaScript 语法检查通过；
- 全量单元测试通过；
- 故障中心、演练、治理和现场操作浏览器流程通过；
- 正式地址 `http://127.0.0.1:8765/` 可实际打开并加载数据。
