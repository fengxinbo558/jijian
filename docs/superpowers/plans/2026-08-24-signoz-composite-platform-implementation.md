# 机鉴第三版 SigNoz 复合底座实施计划

> 设计依据：`../specs/2026-08-24-signoz-composite-platform-design.md`

## 实施原则

- 通过 API、Webhook 和 OpenTelemetry 组合开源服务，不把大型仓库复制进当前项目。
- 所有外部连接默认关闭、只读、可降级和可审计。
- 先完成连接器契约与测试，再让页面消费；页面不自行猜测连接状态。
- 保持现有 SQLite、事件 API 和调查链兼容。
- 不把服务可达等同于已经采集到客户数据。

## 任务 1：集成模型与配置

增加数据来源、连接状态、外部查询和工具调用的数据模型；增加 SigNoz、HolmesGPT 的环境变量配置和安全默认值。

验收：密钥不进入序列化对象；未配置、健康、失败和降级状态可表达。

## 任务 2：SigNoz 只读适配器

实现健康检查、查询 API、告警 Webhook 标准化和受限响应解析。查询请求与返回事实进入调查轨迹。

验收：使用模拟 HTTP 服务验证成功、认证失败、超时、无效 JSON 和结果截断；不得提供修改或删除方法。

## 任务 3：HolmesGPT 只读调查适配器

实现健康检查和 `/api/chat` 调用，保存回答、工具调用与服务元数据。通过现有调查校验器限制结论等级和越权字段。

验收：无工具证据的回答不能变成已确认；服务不可用时规则调查继续。

## 任务 4：数据来源与调查 API

提供来源列表、重新检查连接、SigNoz 告警入口和事件自动补充证据接口。所有接口返回面向普通用户的状态说明。

验收：未配置时返回“尚未连接”；不可达时返回“连接失败”；演练不会被标成真实监控数据。

## 任务 5：明白话界面与信号母线

把“接入”改成“分析真实故障”，把“演练”改成“模拟案例”；将技术告警 JSON 从普通入口移到数据来源区域。增加来源面板和事件数据路径，显示每一步真实状态。

验收：新用户无需理解 Webhook 或 JSON 即可选择入口；桌面和手机均显示完整来源链。

## 任务 6：采集配置与部署说明

提供 OpenTelemetry Collector Linux 示例，覆盖 journald/文件日志和 hostmetrics，并记录如何将数据发送到 SigNoz。说明 SNMP、Redfish、NetBox/OMS 的扩展边界。

验收：配置文件可被语法解析；文档明确安装权限、数据流和卸载方式，不宣称已连接真实机器。

## 任务 7：验证与交付

运行单元、API、评测和浏览器烟雾测试；检查界面文案、控制台错误、移动端与无外部服务降级。保存验证摘要并更新 README。

验收：所有验证具有本轮新鲜输出；任何未验证或受环境阻塞的能力在交付说明中单独列出。
