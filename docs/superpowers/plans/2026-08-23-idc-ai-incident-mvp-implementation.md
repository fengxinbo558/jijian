# IDC AI 故障调查与现场协同 MVP 实施计划

> 设计依据：`../specs/2026-08-23-idc-ai-incident-mvp-design.md`

## 实施原则

- 保持 Python 3.9+、零第三方运行依赖。
- 先写可验证的领域逻辑，再接 API 和界面。
- 每个阶段都能单独运行测试，避免最后一次性联调。
- CC 只产生一次提醒，任何实现不得扩展为电话工作流。

## 视觉计划

- **主题**：IDC 机房运行台，而不是通用 SaaS 仪表盘。
- **颜色**：机柜墨蓝 `#13222B`、设备冷灰 `#E7ECEF`、运行青 `#18A999`、告警橙 `#F39C4A`、危险红 `#D94B4B`、纸面白 `#F7F9FA`。
- **字体**：中文正文使用系统黑体；设备名、SN、IP、机架位使用等宽字体，强化机器身份辨识。
- **布局**：左侧事件队列，右侧调查与处置工作区；移动端退化为列表—详情单列。
- **标志性元素**：把完整 SN 与机架位做成“设备身份条”，外观接近机柜标签，贯穿事件列表和处置卡。
- **克制项**：不使用无意义渐变、玻璃拟态和装饰性统计图；动效只用于新事件进入和危险提示。

## 任务 1：项目骨架与领域模型

创建标准库 Python 包、入口脚本和测试目录。定义统一输入、证据、分析结果、处置卡和事件的数据结构，提供 JSON 往返能力。

验收：数据对象可以创建、序列化和恢复；完整 SN 不被截断。

## 任务 2：归一化、脱敏与规则分析

实现三类输入到统一契约的转换；加入常见密钥、令牌和邮箱脱敏；实现高温、磁盘、内存、网络、服务故障规则，输出类别、严重度、证据和建议。

验收：每类示例都命中预期分类；模型未启用时仍有可解释结论。

## 任务 3：事件关联与 SQLite 存储

实现事件指纹、确定性合并和不确定关联提示。创建 SQLite 表，保存事件、输入证据、分析结果、状态变化和审计记录。

验收：重复告警追加为证据；不同完整 SN 不会被错误合并；服务重启后数据存在。

## 任务 4：可选 AI 增强

实现 OpenAI 兼容接口适配器。只发送脱敏后的压缩证据包，要求返回结构化 JSON；超时、无配置或输出无效时降级为规则结果。

验收：无密钥正常运行；伪造模型响应可增强结论；无证据断言被降级。

## 任务 5：HTTP API

使用标准库 HTTP 服务实现：健康检查、事件列表/详情、通用告警、日志分析、现场上报、状态更新、演示场景回放和静态文件服务。

验收：三种入口均能创建或合并事件；错误输入返回明确错误；API 不执行基础设施写操作。

## 任务 6：Web 工作台

实现事件中心、三种接入方式、事件详情、证据时间线、根因候选、现场处置卡、一次性 CC 提醒、复制沟通文本和状态更新。落实完整 SN、机架位和操作风险的视觉优先级。

验收：桌面与手机尺寸可用；键盘焦点可见；减少动效设置生效；空状态和错误状态给出下一步。

## 任务 7：演示场景与自动测试

加入高温、磁盘、内存、网络四个可重复回放场景。覆盖领域模型、规则、合并、CC 边界、脱敏、存储和 API 集成测试。

验收：一条命令运行全部测试；四个场景从输入到关闭可完整演示。

## 任务 8：启动与交付

提供 README、启动脚本、示例告警调用和配置说明。运行静态检查、自动测试和浏览器实际操作验证，修复后提交最终代码。

验收：当前机器使用系统 Python 一条命令启动；浏览器可完成全部核心流程。
