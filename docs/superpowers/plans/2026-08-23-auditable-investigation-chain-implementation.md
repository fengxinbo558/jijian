# 机鉴第二版可审计调查链实施计划

> 设计依据：`../specs/2026-08-23-auditable-investigation-chain-design.md`

## 实施原则

- 保留 Python 标准库和原生前端，不引入构建链或外部运行依赖。
- 先建立可测试的调查数据，再让页面消费；不在前端临时拼接“推理过程”。
- 所有事实、规则、知识和假设都使用稳定 ID 互相引用。
- 演示数据、规则结果、模型结果和真实工具结果必须明确区分。
- 不破坏现有 API、SQLite 数据和现场安全门；旧事件采用诚实降级展示。
- 每个阶段完成后运行相关测试，最后再执行完整自动测试和浏览器测试。

## 任务 1：知识卡契约与首批知识包

创建 `knowledge/diagnostic_cards.json`，实现加载、结构校验、确定性标签检索和知识覆盖提示。首批放入至少 40 条带来源、限制、反证、验证步骤和禁止推断的知识卡，覆盖存储、内存/CPU、网络、动环、Linux 系统和应用六个领域。

验收：卡片数量和领域配额达标；每张卡具有稳定 ID、来源和禁止推断；检索返回匹配理由而非只有相似度。

## 任务 2：事实提取与字段溯源

新增调查模块，为每次归一化输入生成输入记录、字段来源、事实列表和解析限制。提取块设备、端口、网络接口、温度、ECC/CE/UE、OOM、服务和错误类型等首批实体。

验收：事实都引用原始证据；SN、机架位、UID 和许可明确标为外部提供或未知；演示数据明确标为模拟。

## 任务 3：规则、知识、假设与验证计划

将现有规则分析转换为调查链：记录规则模式和能力边界，召回知识卡，生成竞争假设、反证、缺失证据和分支验证计划。删除固定百分比，改用 `confirmed`、`high_likelihood`、`candidate`、`weakened`、`rejected`。

验收：单一规则命中不产生“已确认”；磁盘、内存和网络保留竞争候选；下一步检查说明目的、风险、权限和对假设的影响。

## 任务 4：事件关联、存储与审计

扩展事件数据加入 `investigation` JSON。创建和合并事件时保存关联键来源、合并理由和调查轨迹；事件详情读取全部原始输入。数据库迁移向后兼容，旧事件显示追踪上线前提示。

验收：明确事件号标为 `explicit`，同设备自动关联标为 `deterministic`；不同完整 SN 不被强制合并；审计日志覆盖调查阶段。

## 任务 5：提示词契约与模型校验

把单一提示词拆为版本化契约文件，模型增强接收事实、知识卡和假设，而不是未经整理的全量数据。校验事实引用、知识卡引用和越权字段；当前无模型时明确为 `rules_only`。

验收：模型关闭时完整调查链可用；模拟模型输出缺引用或包含越权字段时被拒绝或降级；事件记录提示词版本和模型模式。

## 任务 6：证据线路图界面

保留事件队列和设备身份条，详情页新增能力声明、结论等级、下一步检查和纵向证据线路。每个节点可展开查看输入、字段溯源、提取事实、规则、知识卡、关联、假设和结论。原始证据和现场处置卡放在调查链之后。

视觉主题延续 IDC 运行台：墨蓝和冷灰为底，青色表示确认事实，紫蓝表示系统推断，橙色表示待验证，红色只用于安全停止。数据字段使用等宽字体。移动端完整保留调查顺序。

验收：第一屏明确显示分析模式和模拟标签；不出现虚假百分比；键盘可展开节点；桌面和手机均可读。

## 任务 7：测试、评测与交付

新增知识、事实、调查、兼容迁移、API 和页面测试。扩展测试集，分别报告规则基线和可选 AI 模式；没有真实模型配置时不伪造 AI 提升。运行完整单元测试、评测脚本和桌面/移动端浏览器实际操作测试，检查控制台错误并保存截图。

验收：所有自动测试通过；五类场景展示完整调查链；浏览器无未处理错误；报告明确模拟测试不能代表生产准确率。
